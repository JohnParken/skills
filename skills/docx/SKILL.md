## 运行环境与能力边界

- 使用 Python 3.10 及以上版本，要求标准库包含 zlib，且内置 XML 解析器 Expat 版本至少为 2.6.0；解析器不满足条件时报告环境受阻。
- 仅使用 Python 标准库；不要安装或导入第三方包，不要调用办公软件、转换器、Shell 命令、Git 或编译器。
- 在宿主提供的可下载工作目录执行，使用宿主已确认可用的 Python 解释器；下文的 `python` 仅表示该入口。使用 `-I -S -B` 禁用环境路径、site 初始化及缓存写入；脚本只添加自身所在的源码目录以加载本 skill 模块。
- 将输入、输出及任务临时文件放在当前下载工作目录，使用 `./document.json`、`./output.docx` 等相对路径。禁止将任务文件写入 skill 源码目录。创建辅助文件前记录本次新建的确切路径及用途，任务结束按 [任务中间文件清理](#任务中间文件清理) 收尾。
- 按 [requirements.txt](requirements.txt) 确认无第三方运行时依赖；无需运行包安装命令。
- 生成 DOCX；仅使用 ZIP/XML 工具读取、定点编辑和检查已有 DOTX。禁止通过改扩展名转换格式。

## 默认公文格式与覆盖

新建文档时，省略页面和样式设置即可应用以下约定。将其作为本 skill 的默认排版预设；不要据此声称符合完整公文国家标准。

| 对象 | 默认格式 |
|---|---|
| 一级标题（`heading`，`level: 1`） | 方正小标宋简体，18pt，居中，不加粗。 |
| 二级标题（`level: 2`） | 黑体，16pt，左对齐，不加粗。 |
| 三级标题（`level: 3`） | 楷体，16pt，左对齐，加粗。 |
| 四级标题（`level: 4`） | 仿宋，16pt，左对齐，不加粗。 |
| 正文（`paragraph`） | 仿宋，16pt，左对齐，首行缩进 2 字，固定行距 28pt。 |
| 西文 | Times New Roman。 |
| 页面 | A4 纵向；上下边距 2.54cm，左右边距 3.18cm。 |

- 一至四级章节标题必须使用 `type: "heading"` 与对应的 `level: 1` 至 `4`，段落分别引用 `Heading1`、`Heading2`、`Heading3`、`Heading4`；对应样式的 `w:outlineLvl` 分别为 `0`、`1`、`2`、`3`（从 0 计数）。此要求适用于所有主题和显式格式覆盖；禁止用 `paragraph` / `BodyText` 仅修改字体、字号或加粗来模拟标题。标题样式的 `basedOn="Normal"` 只表示继承基础属性，不取消标题身份；预定义但未被段落引用的样式不算已应用。
- 使用零段前、段后间距；标题不缩进，默认使用 1.15 倍行距。为表格使用独立样式；列表、图片段落和页眉页脚沿用基础字体，避免套用正文的首行缩进和固定行距；保留列表自身的编号缩进。
- 上述为默认公文主题。商务、学术主题的页眉页脚使用独立 `Header`、`Footer` 段落样式，字体分别为微软雅黑 / Calibri、宋体 / Times New Roman，均为 10.5pt、1.25 倍行距、黑色、不加粗、左对齐、无首行缩进、段前段后为 0；页码字段结果继承同一样式。正文的 `styles.body` 覆盖不影响页眉页脚。公文主题保留原有基础样式行为。
- 使用顶层 `styles.body`、`styles.heading1` 至 `styles.heading4` 覆盖整类样式；使用段落或标题的 `format` 覆盖单个块，使用 `runs` 中的字符字段覆盖局部文字。保留旧的 `align`、run `font` 和 `page.margin_mm` 用法；具体字段、优先级和示例见 [生成器输入约定](references/generation.md)。
- 使用 `page.margin_top_mm`、`margin_bottom_mm`、`margin_left_mm`、`margin_right_mm` 单独覆盖边距，单位为毫米。不要把 2.54cm 直接写成 `2.54`；应写为 `25.4`。
- 仅在文档中记录字体名称，不下载、安装或嵌入字体。实际显示需阅读端提供相应字体；缺失时可能发生替代，禁止声称已经验证字体或分页效果。
- 编辑已有文档时保留原有样式；不要将文字替换操作解释为自动套用此公文格式。

商务、学术主题的列表使用独立 `ListParagraph` 样式，沿用对应主题基础中西文字体、10.5pt、1.25 倍行距和段后 4pt；不继承正文覆盖或首行缩进，保留编号定义的缩进。公文列表保持原有基础样式；此内置样式不是新增 JSON 字段。

## 默认公文表格与覆盖

按 GB/T 9704—2012《党政机关公文格式》第 5.2.2 条的通用字体字号原则，采用仿宋 16pt；将以下边框、留白、加粗、对齐及跨页行为作为本 skill 的项目排版约定。禁止将整套表格参数描述为国标逐项规定。

| 对象 | 默认格式 |
|---|---|
| 表格正文 | 仿宋 16pt、黑色、不加粗、水平左对齐。 |
| 表头 | 仿宋 16pt、黑色、加粗、水平居中；对 `header: true` 的第一行或 `header_rows` 指定的连续前置行应用。 |
| 西文与数字 | Times New Roman。 |
| 单元格段落 | 首行缩进 0、段前段后 0、1.15 倍行距。 |
| 单元格布局 | 垂直居中；上下留白 1mm、左右留白 1.5mm；无底色。 |
| 边框 | 内外框均为黑色实线，0.5pt。 |
| 表宽与行高 | 默认填满页面可用宽度；允许指定列宽；行高随内容增长。 |
| 跨页 | 声明表头时请求重复表头；默认请求避免单行跨页拆分。 |

- 使用 `styles.table_body`、`styles.table_header` 设置整份文档的表格文字样式，使用顶层 `table_format` 设置表格布局；在单张表格上使用 `body_format`、`header_format`、`format` 分别覆盖。按 [表格配置与示例](references/generation.md#表格配置与示例) 选择字段；不要将布局字段放入文字样式，也不要把正文样式覆盖解释为表格覆盖。
- 同时省略 `header` 与 `header_rows` 时按普通数据行处理；不要自动把第一行数据当作表头。关闭重复表头时保留已声明表头的样式。
- 使用 `header_rows` 声明多行表头，使用 `list_id` 和 `level` 跨说明段继续同一列表实例，使用单元格 `{text, image}` 放置文字及单个 inline 图片。表格 `format.borders` 覆盖表格各边，单元格对象的 `borders` 覆盖其四边；共享边同步到相邻单元格，冲突时拒绝。按 [列表与表格细节](references/generation-details.md) 核对字段与限制；不计算实际编号值、图片解码或分页。
- 保留既有页面边距、标题和正文预设；不要因使用表格而自动切换页面或缩小字号。仅为新建文档应用表格默认值，不对已有文档自动重排。
- 区分国标第 8 章的横排表格要求与本项目的普通表格样式。当前不支持文档内纵横分节、单双页表头朝向或相应页码布局；不要通过交换页面宽高声称满足第 8 章，也不要声称整份文档完全符合国标。
- 将重复表头和避免拆行作为阅读器分页请求；行内容超过一页时，阅读器仍可能拆分。禁止承诺精确分页、行高或打印效果。

表格文字继承 `TableBody` / `TableHeader`，只将单表显式文字覆盖写为直接属性；保留等值覆盖、`false` 及行距模式切换。核对格式时同时检查样式和局部属性，不要求每个单元格重复完整格式。

## 中英文字符与 JSON 语法（生成和替换前必读）

**允许文档内容使用中文、英文或中英混排；必须使用英文半角字符书写 JSON 语法。禁止把“JSON 引号错误”解释为“不支持中文”。**

| 字符用途 | 必须遵守 | 禁止或避免 |
|---|---|---|
| 包围键和字符串值的引号 | 使用英文半角双引号 `"`。 | 不要使用中文弯引号 `“”`、全角双引号 `＂` 或单引号 `'` 充当 JSON 分隔符。 |
| 结构标点和空白 | 使用半角 `:`、`,`、`{}`、`[]`；在字符串外使用普通空格、制表符或换行。 | 不要使用全角冒号 `：`、逗号 `，`、括号 `｛｝［］` 或全角空格代替语法字符。 |
| 字段名与枚举值 | 保留 `blocks`、`text`、`type`、`paragraph` 等约定拼写和大小写。 | 不要翻译成中文字段名，也不要改成全角英文字母；JSON 可解析不代表生成器接受这些字段。 |
| 布尔值与数值 | 在 JSON 中使用不带引号的 `true`、`false` 和半角数字、小数点，如 `1`、`12.5`。 | 不要使用 `True`、`False`、`真`、全角数字或字符串 `"true"` 代替相应类型。 |
| 文本内容 | 保留中文、英文、中文标点及 `“”`、`‘’`；手写 JSON 时将内容中的英文双引号写成 `\"`，反斜杠写成 `\\`。 | 不要全局替换正文中的中文标点或引号，也不要把合法中文内容删掉来规避解析错误。 |
| 模板匹配文本 | 让 `old` 与模板原文完全一致，包括中英文引号、全半角字符和空格。 | 不要自动统一标点或空格后再匹配，以免匹配不到或改错内容。 |

- 将输入保存为 UTF-8（无 BOM）；不要依赖编辑器自动将英文引号转换为弯引号，不要复制 Markdown 代码块边界进 JSON 文件。
- 优先用 Python 字典构造数据，再调用 `json.dumps(spec, ensure_ascii=False, indent=2)` 序列化；让序列化器处理引号与反斜杠转义。Python 字典中的布尔值写 `True`、`False`，序列化结果才是 JSON 的 `true`、`false`；不要把 Python 字典的字符串表示直接当成 JSON。
- 使用 `ensure_ascii=False` 保持中文直接可读；不要声称它能修复非法 JSON。不要对已经序列化的 JSON 再次序列化，以免顶层对象变成字符串。
- 在生成或替换前确认输入可被标准库 JSON 解析器解析；出现 `JSONDecodeError` 时按行号、列号检查错误位置及其前面的分隔符，不要在缺少原始输入时断定是中文内容导致。

按 [中文 JSON 与引号示例](references/generation.md#中文-json-与引号) 核对正反例及自动序列化用法；保留下文的英文和中文示例，按任务选择。

## 生成文档

完成首步自检后，任选下面的英文或中文示例，将其中一个 JSON 以 UTF-8 编码保存为当前下载工作目录中的 `./document.json`；两例均省略样式及页边距，使用默认公文格式。不要同时拼接两例，也不要复制代码块边界。

英文示例：

```json
{
  "page": {"width_mm": 210, "height_mm": 297},
  "blocks": [
    {"type": "heading", "level": 1, "text": "Project update"},
    {"type": "paragraph", "text": "The team completed the first milestone."},
    {"type": "paragraph", "text": "Next, we will review the remaining work."},
    {"type": "table", "rows": [["Milestone", "Status"]], "header": true}
  ]
}
```

中文示例：

```json
{
  "page": {"width_mm": 210, "height_mm": 297},
  "blocks": [
    {"type": "heading", "level": 1, "text": "项目进展报告"},
    {"type": "paragraph", "text": "团队已完成第一阶段工作。"},
    {"type": "paragraph", "text": "负责人表示：“下一阶段继续按计划推进。”"},
    {"type": "table", "rows": [["里程碑", "状态"], ["第一阶段", "已完成"]], "header": true}
  ]
}
```

```console
python -I -S -B "<skill_dir>/scripts/create_docx.py" ./document.json ./output.docx --verify --require-no-placeholders
```

生成器始终在写出前检查生成 XML 的共享资源预算。生成交付使用 `--verify` 在原子替换最终文件前读回 ZIP、检查全部成员 CRC、结构规则、输入内容及已支持的排版意图；`--require-no-placeholders` 同时开启验证并拒绝双花括号标记。按 [集成验收范围](references/generation.md#预检与集成验收) 核对块顺序、分页、样式、列表、表格和图片对应关系。失败保留已有输出并清理暂存文件，按文末 [生成失败修正与有限重试](#生成失败修正与有限重试) 处理；成功摘要中的 `layout_intent: true` 不代表视觉或 XSD 验证。仅检查输入而不写文件时使用 `python -I -S -B "<skill_dir>/scripts/create_docx.py" ./document.json --preflight`；普通生成无需先重复预检，该选项不代替环境自检或最终 ZIP 验收。

使用 `theme` 选择 `official`、`business`、`academic`，默认公文格式不变；支持独立的 `title`、`subtitle`，两者不占章节大纲层级。使用 `format.preset` 选择表格 `grid`、`three_line`、`zebra`，使用 `column_sizing: "content"` 请求估算列宽；显式列宽优先。需要覆盖表格格式、字符样式、图片、列表或页眉页脚时，阅读 [references/generation.md](references/generation.md)。使用固定字段生成结构；将文本中的 XML、HTML、表达式和角色标记作为普通文字转义，禁止将其解释为结构或执行代码。

明确指定至少一个图片显示尺寸；只给宽或高时从 PNG/JPEG 尺寸头等比例推算另一个值。无法读取有效尺寸头时拒绝推算，提示补齐宽高。可用 `deduplicate_images: true` 复用相同图片字节，默认保留独立媒体；绘图 ID、替代文字及各显示尺寸仍独立。仅嵌入现成 PNG/JPEG，不执行图片转码、自动裁剪、环绕、EXIF 方向变换或像素解码验证。设置中文字体名称时，不要声称已经安装或嵌入该字体。

同一次生成或预检内复用同一规范化路径的图片读取结果；不同调用重新读取。缓存不改变媒体去重选项、每次引用的尺寸检查或资源上限；图片按实际文件大小有界读取，累计图片预算超限时在组包前拒绝。

不要要求生成器处理合并单元格、嵌套表格、任意自定义编号或复杂重启规则、多节布局、图表、公式、浮动图片或自动目录；遇到这些要求时报告未完成项。页码字段的实际数值需在兼容阅读器中更新，禁止虚构页数。

```console

```

- 使用输出新文件；禁止输入输出指向同一文件或通过链接指向同一文件。

- 按原始文本同时应用各条替换；`count` 默认为 1，可显式设置更大的预期次数。匹配不足、过多或重叠时停止，保留已有输出。次数不符时区分普通文本次数异常、跨文本/run 拆分、受保护或复杂容器、选定部件中缺失等诊断；诊断不扩大可编辑范围。
- 默认仅编辑 `word/document.xml`；需要时用 `--parts word/document.xml word/header1.xml` 指定真实存在的正文、数字后缀页眉或页脚部件。
- 仅替换单个普通 `w:t` 节点内的文字，保留 run 格式；禁止跨 run、字段、修订、超链接、批注范围或复杂容器自动替换。替换值仅支持单行文本。
- 对跨段落的复杂字段、批注及移动修订范围同样禁止替换其内部文字；选定部件存在未闭合、错序、重复或缺失必要 ID 的受检范围标记时，停止编辑并保留已有输出。重叠检查包括同一搜索词自身的重叠出现。
- 按最近祖先的 `xml:space` 判断是否保留空白。目标节点含边缘 XML 空白（空格、制表、回车、换行）但未声明或继承 `preserve` 时，拒绝编辑，不自动裁剪或激活原有空白。保留全角空格、不换行空格及明确保留的空白；允许替换值显式新增边缘空格。
- 拒绝编辑含 XML 注释、处理指令或未知属性的目标文字节点，以及含未知扩展或复杂内容的目标 run。可编辑普通文字之外的内容控件、未知容器等不在受控替换范围内；不要通过删除这些内容强行替换。
- 将简单占位符完整放在同一个 run 中；不要模拟 Jinja 表达式、过滤器、条件或循环。动态行数据应在生成器的 JSON 表格数据中构造。
- 使用 `--require-no-placeholders` 检查剩余双花括号标记，包括段落内跨 run 拆分的标记。对字面双花括号文本省略此选项并人工核对。

保留未修改 ZIP 部件的内容字节；不要声称整个 ZIP 或修改过的 XML 字节不变。修改部件写出前重新解析并比较全部节点及属性值；序列化不能保真时拒绝编辑（例如某些字符引用的空白规范化），不以结构检查通过代替保真。未知扩展部件可原样保留，但不要声称已理解或验证其语义。

## 基础结构检查与验收

使用 `--verify` 成功生成时，已在发布前完成 ZIP、结构与输入内容覆盖核对，无需重复执行下述独立 CRC/结构/文本回读命令；仍须确认本次文件存在且非空，并按需求核对格式与交付链接。未使用集成验收或检查已有文件时，先验证本次指定的目标文件真实存在且非空，再执行结构检查；禁止仅凭生成函数返回、打印的路径或其他会话留下的文件交付。使用标准库完成与文件列表核对等价的验证，不调用 Shell 的文件列表命令：

```python
from pathlib import Path
import zipfile

output = Path("./output.docx")  # 与本次生成目标保持一致。
if not output.is_file() or output.stat().st_size <= 0:
    raise RuntimeError("目标文件不存在或为空")
with zipfile.ZipFile(output) as package:
    if package.testzip() is not None:
        raise RuntimeError("DOCX ZIP 完整性检查失败")
print(f"./{output.as_posix()} exists=True size={output.stat().st_size} zip-ok")
```

禁止用其他目录中的同名文件代替该目标；验证失败时停止本次交付，新建文档仅可按下述有限重试规则修正后重新验收。无法修正时报告实际失败。以上步骤不替代下列结构检查：

```console
python -I -S -B "<skill_dir>/scripts/office/validate.py" ./output.docx --require-no-placeholders
python -I -S -B "<skill_dir>/scripts/read_docx.py" ./output.docx --include-related -o ./checked-content.txt
```

1. 核对 ZIP 完整性与必需部件；解包脚本会读取成员并检查 CRC、路径和重复名称。单独使用 `zipfile.testzip()` 时确认返回 `None`。
2. 运行结构检查并根据非零退出码定位问题；仅在已授权且可确定的范围内修正，新建文档遵循下述重试规则。检查 XML 可解析性、必需根节点、内容类型覆盖、内部关系目标与引用、样式/编号引用、范围批注锚点及修订的基本 ID/作者属性；同时检查显式表格跨度、纵向合并连续性及编号层级/覆盖/重启的已实现规则。按 [检查范围](references/inspection.md#进阶检查范围) 审阅带位置的错误及 `unverified` 警告；警告不是该能力已通过验收，不得静默忽略。
3. 对照输入核对文字、表格、图片引用和未填充占位符，确认中文、英文及正文引号原样保留。对提取器不覆盖的内容检查相应 XML；不要把成功解压或解析当作 Word 实际打开验证。
4. 生成时对照输入核对 `word/styles.xml` 和 `word/document.xml` 中的样式引用、字体、字号、缩进、行距及页面尺寸；未显式覆盖时核对默认公文格式，显式覆盖时按实际优先级核对。先对照用户要求的章节结构，确认标题文字、顺序、数量及层级已正确写入生成输入，再逐段核对实际 `w:pStyle` 为对应的 `Heading1` 至 `Heading4`，且引用样式的 `w:outlineLvl` 为 `level - 1`；仅有字体差异或样式定义存在不能通过标题验收。`--verify` 已按生成输入检查标题样式引用和大纲级别，但不能判断被误写为 `paragraph` 的文字是否原本应是标题；该输入语义核对不得省略。对表格额外核对独立正文/表头样式、边框、留白、垂直对齐、底色及重复表头/避免拆行标记；默认不得写入固定行高。基础结构校验器不会替代这些排版值检查，也不能验证字体存在或页面显示效果。
5. 编辑时核对未修改部件的内容字节；检查失败时保留原始文档和已有输出。禁止跳过失败后报告完成。
6. 仅报告实际执行的检查。不要声称已验证完整元素顺序、所有 OOXML 扩展、图片解码、修订语义、字体或页面布局。
7. 按需求、操作、验证顺序执行；交付时仅提供简要依据和实测结果。需要事实或引用时依据用户材料或已核实来源，禁止为补全内容编造来源。

校验器不会自动修复文档，也不会读取或下载 XSD。输入目录可直接检查；打包文件直接读取成员进行有界内存校验，并核对 DOCX/DOTX 扩展名与主内容类型是否一致；全部成员均读取并核对 CRC。`--original` 修订对比仍使用暂存解包路径。指定 `--original` 即在结构检查通过后执行修订文本对比，不会豁免继承错误。

保留解析上限：最多 4096 个 ZIP 成员，单成员 32 MiB，总解压内容 128 MiB；单 XML 16 MiB、深度 128、元素 200000。拒绝 DTD/实体声明及外部解析；遇到上限时报告受阻，不要自行绕过。

将实际检查结果记入执行过程：`已通过 ZIP、XML 和已实现的结构规则检查；未执行 XSD 校验及视觉验证。` 不要将该声明写入文档正文。文档生成或编辑业务优先返回宿主支持且已核实指向本次文件的可点击文件链接；宿主仅支持相对文件名时返回例如 `./示例报告.docx`。不得猜测下载 URL、拼接掩码或直接采用输出日志中的地址；链接只能指向真实交付产物。失败时报告原因，不要返回不存在的文件名。Skill 维护任务按实际修改和测试结果交付说明。无法核实的信息应明确说明，禁止编造来源或验证结果。

不要承诺旧 DOC 转换、PDF 导出、页面截图、精确页数、字段重算或视觉验证。将 System Role、temperature 和输入长度限制交由支持这些配置的宿主实现，禁止仅凭本文声称已经设置。不要为过滤角色标记而删除原文或机械截断长文档；超出上下文时分段处理并核对覆盖范围。

### 生成失败修正与有限重试

由执行本 Skill 的助手按以下流程组织新建文档任务；CLI/API 每次仍只执行一次，不会自动修复或循环重试。API 默认 `verify=False` 保持兼容，按本流程调用时必须显式设为 `True`。此规则不扩大受控编辑范围，也不覆盖首步自检失败时立即停止的要求。

1. **生成并验收。** 首次生成及每次重试均开启 `--verify`（API 使用 `verify=True`），按任务需要保留 `--require-no-placeholders`。使用已确认的任务目录和目标文件；记录尝试序号、返回码及实际诊断。验证失败时不交付，不将保留下来的旧文件当作本次成功结果。
2. **按诊断判断能否修正。** 仅修正有明确依据且不改变用户意图的输入或调用错误，例如 JSON 语法、可确认的字段拼写、调用参数，或使用用户已提供的值补齐占位符。只更正当前任务内可核实的资源引用，不猜测路径、缺失内容或格式意图。遇到环境/写入异常、安全校验失败、资源超限、不支持的功能、信息不足，或正确输入仍触发内容/排版意图不一致时，停止并报告原因；不得以重试替代环境修复或 Skill 维护。
3. **修正后有限重试。** 首次尝试之外最多重试 2 次，即同一生成任务最多调用生成器 3 次。每次须先完成针对诊断的具体修正并记录改动；禁止原样重复执行、换文件名或路径重置计数。修正后同一错误再次出现、无法确定下一步修正，或两次重试均失败时停止，说明失败位置及需要补充的信息。
4. **重新完整验收。** 每次重试都重新执行集成验收，不能沿用上次结果。禁止关闭校验、忽略警告、放宽安全限额、删减用户内容或在普通文档任务中修改生成器/验收器来获得通过。仅在本次生成成功且验收通过后，再核实目标存在、非空及交付链接；已完成的集成检查无需重复运行独立 CRC/结构/文本回读命令。
5. **据实交付。** 成功时简述实际检查结果；发生过重试时说明重试次数和修正项。失败时保留原始材料与已有输出，报告已尝试次数、最后诊断和未完成项，不返回失败产物或冒充本次产物的旧文件。成功或终止重试后均按下节清理本次中间文件。执行记录不写入文档正文，不声称已完成视觉或 XSD 验证。

### 任务中间文件清理

由执行本 Skill 的助手负责生成、编辑和检查任务的收尾清理；脚本自身的暂存文件清理不等于整个任务的清理，也不会自动删除调用方的 JSON 或脚本。

1. **记录归属。** 创建前记录本次新建且此前不存在的中间文件、目录的确切相对路径及用途。工作副本和解包目录使用当前任务目录内新建的独立子目录，不复用已有目录。不得把用户上传的原件、模板、图片、用户提供的 JSON、已有输出或其他任务文件列为可清理项；文件名相同或扩展名相同不能证明归属。无法确认本次创建的文件应保留。
2. **成功后清理。** 完成全部生成、编辑及结果验收后，交付前删除清单内已无后续用途的中间文件，包括助手生成的输入 JSON、替换规则、临时 Python 脚本、仅供验收的文本/结构回读结果、日志、临时图片、解包工作副本及未选用的中间 DOCX。保留最终交付文件，以及用户明确要求的源码、JSON、日志或其他辅助产物；不得删除交付文件依赖的外部资源。
3. **重试及失败收尾。** 仍在重试或等待必要输入时，保留继续执行所需的材料。任务最终失败或停止时，清理本次产生且不再需要的中间文件；仅保留定位或恢复必需的最少材料并说明用途及位置。始终保留用户原始材料、已有输出，以及尚未确认恢复完成的事务备份；禁止将恢复备份当作普通临时目录删除。
4. **按清单删除。** 使用 Python 标准库逐项处理已确认归属的路径，不使用 Shell 清理命令、通配符或全目录扫描批量删除。限制在已确认的任务目录内，不跟随符号链接；清理路径或其父级出现链接、类型变化或归属不明时保留并报告。目录仅在已知文件清理后确认为空时删除，禁止递归删除可能混入其他文件的目录。已不存在的清单项可跳过。
5. **核实收尾。** 清理后再次确认最终交付文件存在、非空且链接仍指向该文件；仅在文件未变化时复用已有验收结果。遇到权限或占用导致无法清理时，不扩大删除范围，不为清理而重新生成文档；据实说明未清理项和原因，不声称已全部清理。清理记录不写入文档正文。
